Roadmap

What is done, what comes next and what is not planned. No dates: they would be guesses.

Done (0.1.0 to 0.6.1)

  • Deterministic simulation and replaysSame project, seed and inputs give the same StateHash. Verified on macOS Apple silicon and macOS Intel (x86-64 binary under Rosetta on Apple silicon).
  • The editorScene tree, voxel and terrain tools, inspector and a Play mode.
  • Go and visual scriptingGo compiled to WebAssembly, or node graphs for people who prefer not to type.
  • The Hub, signed updates and installersProjects and engine versions side by side with templates, installs only from a signed list of files, and installers for Windows, macOS and Linux (unsigned for now).
  • Audio, particles and block lightA mixer with 3D sound, a particle system and coloured block light.
  • Genre templatesPlatformer, puzzle, strategy and survival, each a project you can change.
  • MultiplayerOpt-in deterministic lockstep with a join link, host and join dialogs in the Hub, and a listen server in the editor.
  • Polish and safety fixesDisplay scale, a smoother editor and input, and project paths that cannot be used to write outside the project on Windows.
  • Asset manager, code editor and studio toolsFolders, drag and drop, rename that rewrites references and a trash with undo. A code editor with search, autocomplete and live errors, and model, texture and visual script editors in their own windows.
  • Water, buoyancy and a richer lookFine water by default, floating and sinking bodies, optional swell, parallax relief with normal and specular maps, and look sliders.
  • Navigation and AIPathfinding for walkers, swimmers, climbers and flyers, behaviour trees, perception, and a typed blackboard for scripts.
  • A building guide for agentsRules, 16 styles and block palettes, so an AI agent can plan and review a house through the MCP server.

Next

  • Windows, Linux and macOS Intel: first CI and hardware runsResults are recorded on the Platforms page.
  • Linux AppImage and macOS Intel disk imageBoth need tools that are not set up on the build machine yet.
  • Windows ARM64 and Linux ARM64 buildsAdded once the first runs are in.
  • Multiplayer over the real internetTests so far run on loopback and in simulation.
  • Hub self-update on macOS and LinuxIt is available for Windows installs today.
  • Ready-made creaturesHealth, damage, loot and spawning as a reusable layer. Today the survival template codes them by hand.
  • French documentationThe site is bilingual, the docs are not.
  • Minimap and selection polishFrom the gaps found while building the templates.
  • Code signingWhen there are enough users to justify it.

Later

  • Water that seeks holesFluid does not spread toward the nearest drop yet.
  • Dedicated server polishEasier hosting and moderation, once real games use multiplayer.
  • Web and WebGPUNeeds a new renderer.
  • MobileNeeds a new renderer and new input.
  • More templatesMore genres, once the first four settle.

Not planned (for now)

  • ConsolesTheir SDKs are closed and need agreements.
  • Closed-source pluginsBurrow is MIT licensed and open to read.

Report a problem

Bug reports go to the issues page of the public repository. Please attach Burrow.log, which sits next to the executable.

If the problem is about speed, also start the game with BURROW_PERFLOG=csv and attach the burrow_frames.csv file it writes on exit.
