Features

  1. 1

    Water

    Water keeps its volume. A spring over a cliff falls and fills the basin below.

  2. 2

    Colored light

    Lava, torches and glowstone tint the blocks around them. Caves stay dark until you light them.

  3. 3

    Deterministic

    The same seed and inputs give the same state hash on x86-64 and ARM64. Verified on macOS Apple silicon and macOS Intel (x86-64 binary under Rosetta on Apple silicon).

  4. 4

    Any genre

    Templates include a platformer, a strategy game and a physics puzzle. Their rules are scripts, not engine code.

A

Water

Water moves in sub-cell bricks, keeps its total volume and updates every tick. Fine water is on by default in every template. Floating bodies feel it: boats displace water, and optional swell rolls the surface. The clip shows a spring falling over a stone cliff into a basin.

app.AddPlugins(&fluid.Plugin{Config: fluid.Config{Fine: true}})

B

Light

Block light has red, green and blue channels. Skylight is separate, so caves are dark. Lava, torches, glowstone and lanterns have default colors, and any block can set its own.

  • 0 to 15 per channel
  • RGB block light
  • separate skylight

C

Editor

Dockable panels and voxel tools, plus model, texture and visual script editors that open in their own window: zoom and pan, mirror drawing, layers, a searchable node library and a live debugger. Animation, character, particle, audio and level tools, an asset manager, a code editor and Search in Project. Play and Stop restore the world exactly. Undo covers every edit.

burrow new mygame -template builder
cd mygame && burrow edit

Details

Gameplay is a short Go script

Scripts are written in Go, compiled to WebAssembly and run inside the simulation: sandboxed, metered and deterministic. This one spins whatever it is attached to.

burrowsdk.Register(burrowsdk.Script{
	OnTick: func(self burrowsdk.Entity, dt float64) {
		t, _ := burrowsdk.GetTransform(self)
		t.Rot[1] += 90 * float32(dt)
		burrowsdk.SetTransform(self, t)
	},
})

20 Hz

Same seed, same inputs, same hash

A fixed 20 Hz simulation. Every change is a journaled command, so a session replays exactly, and a headless run can check it. Same project, seed and inputs give the same StateHash. Verified on macOS Apple silicon and macOS Intel (x86-64 binary under Rosetta on Apple silicon). The simulation uses integer math or explicitly rounded floats with a deterministic math library; rendering is not covered.

A Vulkan renderer with a shader ladder

Shadows, atmosphere, clouds, bloom, ray-traced shadows and occlusion, TAA, FXAA, SMAA and FSR upscaling, from low to ultra. It needs a Vulkan-capable GPU.

Updates you can verify

The Burrow Hub keeps your projects and engine versions side by side and updates only from a signed list of files. It sends no telemetry. You can check a release yourself, offline:

burrowrelease verify -manifest manifest.json -pub burrow-release.pub

Automation

Everything the editor does also works without a window: from the command line, an MCP server or JSON commands. Scripts, tests and AI agents can create and edit worlds, take screenshots and replay sessions.

Read the automation guide

burrow agent --stdio ./mygame      # the editor as an MCP server
burrowd                           # engine sessions over MCP (stdio)
burrowctl --help                  # the same session API as a JSON CLI

About Burrow

Burrow is an engine, not a game. A sandbox, a builder, a platformer, a puzzle, a strategy game and a survival game are all projects on the same engine.

It is young. The API is v0 and will change, and multiplayer is new in 0.2. See the Platforms page for what has been tested where.
