0.8.3 - 2026-11-06

Latest2026-11-06

  • Fixed: two buttons bound to the mouse wheel, one per direction (scroll with scale 1 and scale -1), were both pressed by any notch: a button takes an analog input by its length, which ignored the sign, so a game that changes slot with hotbar_prev/hotbar_next saw one step forward and one back and nothing moved. A wheel binding now presses a button only in the direction of its scale. Test TestScrollButtonsArePerDirection.
  • Added: a game customizes its loading screen and a network client's wait: gogame.Game.Loading (LoadingScreen: Title, Paint(cv, w, h, t, title, stage) draws the whole screen, Ready()), engine.LoadingScreenPlugin.Hold/Stage/Paint and game.Window.OnLoading. For a client (gogame.Connect/Join) the screen stays up until the connection is complete (netplay.Guest.Ready: the server accepted it, its player exists, the terrain under it arrived) and the game says it is ready (LoadingScreen.Ready: its first data from the server): nothing of the world shows before. Stages given to Paint: world, connect, terrain, arrival. The simulation is not paused while a Hold keeps the screen up.
  • Fixed: Enter in a text field only sent its event; it now also runs the ui: parts of its action like a button (sim:chat:say;ui:set:chat_text=;ui:hide:chat_input sends, clears and closes). Test TestInputSubmitRunsItsUIActions.
  • Added: the server streams the terrain, as Minecraft does (replica.ServerConfig.StreamBase, always on for netplay.StartHost): every non-empty chunk of the base terrain in a client's view is sent whole (version 0, compressed once and shared: basestream.go), not only the chunks the game edited; the first edit of such a chunk is a delta from the terrain (the client holds it: chunkEnt.baseDelta, the whole chunk only past MaxDeltaEdits) and starts the delta references; terrain chunks are deflated at BestCompression (once, shared: 10% under BestSpeed on biome terrain; a shared dictionary added only 4% more and a protocol change, so none), and a client's frame generates at most 8 new terrain chunks (maxGenPerFrame), so a joining player does not stall the server's ticks. A client (netplay.Join) removes its base terrain (ChunkMap.SetBase(0, 0, nil)): it generates nothing, needs no seed and no generator of the game, and the pin net.stream_base makes a client of another kind refuse; the world seed is no longer a pin. The client's prediction waits for the chunk under the player (Client.HoldsChunk, 3 s at most) instead of walking through the void. Cost: the terrain in view crosses the network once per client (a few hundred KiB to a few MiB, at the 256 KiB/s budget). Tests TestStreamBaseSendsTheTerrain.
  • Added: gogame.Ctx.BlockBoxes(x, y, z): the boxes that make the shape of the block at a cell, {minX, minY, minZ, maxX, maxY, maxZ} in blocks from the cell's corner (the selection boxes a ray tests, resolved for that cell: stairs with their corner shape, a slab low or high, a torch, a fence with its connections); nil for air and for a full cube. A game that draws something around or over a block (the mining cracks, an outline) follows the model with it instead of the whole cell. Test TestBlockBoxesFollowTheShape.
  • Fixed: on a network client, typing in a text field of the game UI also played the game: the input sent to the server carried the walking and the buttons of the keys pressed (typing "wood" in a command box walked the avatar and pressed the game's keys). While a text field has the focus (UI.FocusedIsInput), internal/netplay.InputFromState sends no walking and no buttons, only the look. Test TestTypingSendsNoGameInput.
  • Fixed: gameui grids and lists, found with the project's inventory: (1) a click that moved a few pixels between the press and the release became a drag, and released over its own cell the click was lost; at 4K a hand moves 6 pixels easily. The drag threshold now grows with the interface scale, and a release over the cell the press started on, without the pointer ever having left it, is a click (a drag that left the cell and came back still cancels); (2) an item picked up by a first click now follows the cursor like a dragged one until the next click puts it down (UI.carried); (3) Widget.ScrollOffset() exposes the offset a list uses to find the row under a click, for a painter that draws the list itself: the project's skin counted the wheel on its own and never saw it (a modal screen zeroes the app input before the skin reads it), so the engine scrolled the list while the skin drew the top rows, and clicks landed on rows other than the ones shown. Tests TestClickWithJitterIsStillAClick, TestDragStillMovesAndCancels, TestListScrollOffsetIsExposed, TestClickPickedItemFollowsTheCursor.
  • Fixed: in a network session the window and the server never agreed on where the player was (measured up to 1.6 blocks), so the server aimed, broke and picked up from a place the player did not see, and any correction felt like a rollback. The client and the server stepped the player with two different models (the first person controller at frame rate, with its own physics and creature collisions; the server one step per input received, about 15 a second), and the controller kept its prediction forever. Now, as in client-side prediction with server reconciliation (Gambetta; Overwatch's command frames): the server applies every movement input once, in order, one per tick (a backlog two per tick; net/replica.Server.runTick, test TestServerAppliesEachInputOnceInOrder); the walk model is one exported function, netsim.Walk (netsim.WalkState), that the server's moveNode and the client both call; a client with a first person controller builds one input per tick of real time, predicts it with netsim.Walk, keeps it until acknowledged and draws the prediction interpolated between its last two ticks (app.Controller.SetPrediction / SetPredicted: the controller runs no physics of its own then); each server frame compares the node's position for the acknowledged input (FrameInfo.InputAck, replica.Client.InputSeq) with the prediction, and on a difference (a knockback, a push, water, a teleport) restarts from the server's position and replays the inputs in flight, the on-screen jump fading over a few frames (internal/netplay predict.go). Same inputs, same positions: walking, turning, jumping and climbing steps need no correction (test TestPredictionMatchesTheServerExactly, a real netsim server four inputs behind).
  • Added: BURROW_NETSTATS=1 on a dedicated server logs the replication every 10 s (chunks and fine water sent whole or as deltas, entity updates, paused ticks, and per client the pending updates and frame sizes).
  • Added: netsim.Input.EyeX/EyeY/EyeZ/HasEye: a network client sends where its camera is with every input (internal/netplay.InputFromState, from app.FrameState.CameraPos), and gogame.Ctx.EyeOf(player) reads it. The server walks the node a network trip behind what the player sees; a game aims the player's rules from this eye (after checking it is near the node) so the block or creature under the crosshair is the one hit. Stored in the player registry behind flag bit 4: a registry whose inputs carry no eye (alone, older saves) encodes and hashes exactly as before (test TestInputEyeRoundTripAndOldEncodingUnchanged).
  • Fixed: the wind sway still read as a loop: its sines kept one tempo. The phase of each spot now also wanders with a noise moving in time, and the whole field hurries and calms down together over tens of seconds (a bounded phase drift: a tempo varying with the time would grow without end on a long session). voxel.vert.spv rebuilt with cmd/burrowshader.
  • Fixed: a networked first person controller never followed a move of its player node by the game on the server (a respawn, a teleport, a return to a shelter, a knockback): it keeps its own predicted position and never wrote nor read its node in a session, so the camera stayed where the player had been while the server placed them elsewhere (and aimed their rules from there). gogame.Ctx.SetTransform / SetPos on a player node now count the move in scene.Player.Warp (replicated; 0 adds nothing to the hash), and the controller takes the node's position when it changes (followWarp), keeping its look. Tests TestNetworkedControllerFollowsWarps.
  • Fixed: sneaking did not reach the server: the actions sneak and crouch were plain sequential button bits, so the server's walk model (which reads netsim.ButtonCrouch) walked the player upright, at full speed and off ledges. Both now set ButtonCrouch on the client (internal/netplay.specialButtons) and read it on the server (gogame buttonBits); sequential bits stop at 28 (bit 29 is ButtonCrouch). Test TestSneakIsSentAsCrouch.
  • Added: gogame.Game.RulesOnlyEdits (and dedicated.Options / netplay.HostOptions.RulesOnlyEdits): the server refuses the block edits a client sends directly (netplay.EditKinds: set_block, fill_box, fill_sphere, micro_edit, block_micro_event). The default whitelist only limits their rate and range, and checks no capability: a modified client could edit the world freely in a game whose rules break and place blocks themselves.
  • Fixed: on a network client, the look sent to the server was not the one the player saw: internal/netplay.InputFromState accumulated the mouse into its own yaw and pitch, from 0 and with the opposite sign of the first person controller's (and without its sensitivity). The server aimed the player's rules (breaking, placing, hitting, using) in a mirrored direction, so the block under the crosshair was never the one hit and no crack showed. The input now carries the controller's Look() when there is one (the mouse delta, with the controller's sign, only without it). Test TestInputCarriesTheControllersLook.
  • Fixed: the wind sway of leaves and plants read as a loop: every block followed the same two sines with one phase (a period of 2 to 4 s) shifted by its position, so the same swing came back and a regular wave crossed the forest. shaders/voxel.vert now scales it by gusts (a slow value-noise field drifting with the wind), offsets the phase of each spot by noise and sums three sines with unrelated frequency ratios. It stays a continuous function of the world position (vertices shared by neighbouring blocks move together) and the wind strength settings are unchanged. voxel.vert.spv rebuilt with the embedded glslang (cmd/burrowshader; make shaders with glslc gives the optimised binary).
  • Added: project tint settings, textures/tints.json beside the block overrides (read again on every override reload): the fixed colour (plains) and the four climate corners (biomes) of the grass, foliage and water tints, a global saturation and brightness, the tint gain (replaces blocktex.TintGain on the CPU paths and the look's tint gain), whether a pack's tintable textures are normalised and to which reference level, and a per-block tint (blocks: none, grass, foliage or water). Every field is optional; without the file nothing changes (blocktex.Tints, TintGainInForce).
  • Added: block textures of several sizes. A project override (textures/block/<name>.png) keeps its own size, a power of two up to blocktex.MaxOverrideSize (256; another width goes down to the power of two under it) instead of being resampled to the pack's 16 px, and blocktex.BuildLayers brings every layer of the set to the largest texture size (nearest neighbour, so pixel art stays sharp), up to blocktex.MaxMixedSize (256). A project whose textures all share one size is unchanged. Memory grows with the square of the largest size (about 400 layers x 3 maps: 64 px ~ 25 MiB, 256 px ~ 400 MiB with mips).

0.8.1 - 2026-11-05

2026-11-05

  • gogame: network games for a Go game, dedicated server only (no listen server). gogame.Serve runs the game as a dedicated server (the burrow-server data directory, world saves, bans, admin console; gogame.InitServer writes it; Game.NetScene is the scene it runs), gogame.Join / Connect and the menu action net:join:<link> play on a server, and Main gets -serve DIR, -init-server DIR, -connect LINK, -name. The server alone runs OnTick; OnFrame and the UI run on the clients only.

  • gogame: Ctx.Players (the connected players, or the one local player when played alone), Ctx.ActionOf (a player's input action), Ctx.PlayerBytes / SetPlayerBytes / DeletePlayerBytes (per-player data, replicated to its owner only through component gogame.pdata tagged owner:<id>, saved with the world), Ctx.InSession, and on the client Frame.LocalPlayer, Frame.PlayerBytes, Frame.Session plus the frame-side effects Frame.UISet, UISetItems, UIShow, UIHide, CameraShake, CameraCut, ParticleBurst.

  • gogame: Frame.View (a read-only WorldView of the voxels and nodes, the same interface as *Ctx has), Frame.LocalNode and Frame.MouseButtons, so a network client can draw a minimap and animate the arm from its replicated copy; Main gets -ctl DIR <command>.

  • gameui: drag and drop in a grid: a press on a filled cell and a move of 6 pixels carry the item (drawn under the cursor, its cell lit); releasing over another cell of the grid emits the same move event as click then click, releasing anywhere else cancels. A plain click is unchanged.

  • gameui: Ctrl+V (Cmd+V) pastes the system clipboard into the focused input field and Ctrl+C (Cmd+C) copies the field (UI.FocusedText); a paste is one line of at most 512 printable characters. Declarative input fields had no clipboard.

  • Fixed: on a network client the first person controller did not know its player id, so the replicated copy of the player's own avatar was drawn like another player's (a full body a step behind the camera, and the torso visible when looking down); netplay.Guest now tells the controller its player id and the engine draws only the arm.

  • Fixed: a network client sent only the buttons held at the instant of a submission, so a click, a tap or one notch of the wheel between two submissions never reached the server; the buttons seen since the last submission are now sent together (internal/netplay.Guest).

  • gameui/uiplug: a gameui_event carries the sender (EventCmd.Player, InEvent.Player); the server's whitelist forces it to the sender's id. The hash of an event is unchanged when it is 0 (a game played alone).

  • internal/dedicated: Options.Customize lets the caller adjust the options the game is built with (used by gogame.Serve).

  • Fixed: a Go game (gogame.Run) ended when a menu asked for a world (world:play, world:create) or the title: it now rebuilds the game in the same window, like burrowplay. Joining or hosting a network game is not served by a Go game yet (back to the title).
  • Fixed: Game.Generator was ignored by a runtime scene switch (the switch rebuilt the plain project terrain), so a game that went through a menu lost its custom terrain. The wrapper is now process wide like the other project data and applies to every scene switch.
  • gogame: the game state holds up to 1 MiB per key and 4 MiB in all (was 64 KiB per key; MaxStateTotalBytes is new). The hash of an existing game is unchanged. A server still sends the state component to clients only when its JSON is at most 64 KiB (wire.MaxCompData), so a larger state is not mirrored to remote clients (documented in docs/gogame.md).
  • gogame: Ctx.SetVoxels (up to 65536 block edits in one call, all or nothing) and Ctx.FillVoxels (a box of up to 1 048 576 cells).
  • gogame: Game.Generator lets a Go game wrap or replace the terrain generator of runtime.generator, and worldgen.Decorated adds features (ores, ruins, structures) to any base generator while keeping its chunk layers, registry binding, far-terrain sampling and biome tint. engine.SetBiomeGen follows Unwrap() so a decorated biome world keeps its tint. The decoration ID is part of the world identity. A project without Game.Generator is unchanged (same StateHash).
  • Fixed: maps made with the full block registry no longer fail to open. A .voxworld is now matched to the registry by block name and renumbered (it used to require an identical list, and 0.7 had renumbered 332 of the 385 cubes). A block the registry lacks is named in the error.
  • runtime.block_packs (for example ["minecraft"]) lets a project enable the optional packs; burrow migrate adds ["minecraft"] to projects made before 0.7, when that catalog was built in.
  • runtime.block_registry + burrow blocks export: the project keeps its own copy of the block registry (ids and properties), independent of the engine version; burrow new creates it, burrow build ships it, and the StateHash of the templates is unchanged by it. burrow blocks packs lists the packs.
  • Breaking, removed: the player rules. The engine no longer has hit points, death, lives, respawn or a kill plane: the player.health component, the lives, respawn_delay, respawn_at, kill_plane and kill_y fields of game.mode, the commands scene_player_hurt, scene_player_die, scene_player_respawn, scene_player_checkpoint and scene_player_rules, the player.died and player.respawned events and the controller's "dead" input lock. A game keeps these in its own state and decides in its own code (a Go game: Ctx.State, Ctx.SetPos). A level's kill_y and bounds still return an actor to the level's default spawn. game.mode keeps the player prefab, the input map and the spawn points; the creative inventory and the player capabilities (player.move, player.build, player.interact, player.inventory, player.controls) stay. Scenes, prefabs and variants saved with the removed parts still load (they are dropped on load) and burrow migrate removes them from the files. The StateHash of every project changes (a hashed component is gone): saves and replays from before do not load, and scripts/portability-golden.txt is re-recorded (identical on darwin/arm64 and darwin/amd64; Windows and Linux are for CI to confirm).
  • Removed: matchmaking. The self-hosted matchmaker (internal/matchmaker, burrow-server matchmaker ..., ratings and queues), its wire contract (net/mmapi), the dedicated server's "matchmaking" mode and matchmaker section, burrowplay -matchmaker/-queue/-party/-region/-accept-invites and docs/matchmaking.md. A rating and queueing service is a platform product, not an engine feature. burrow-server still hosts persistent and lobby servers.
  • Removed: the survival, topdown_strategy and physics_puzzle templates and their examples/tpl_* pilots. They were complete games, not engine features. platformer stays as the reference template (the burrow gen and parity tests use it) and lobby_match as the lobby fixture. burrow migrate still converts projects made from them.
  • gogame: generic engine primitives on Ctx, so a game no longer needs the WASM SDK for them: BlockInfo, VoxelInfo, BlockNames, Light, ParticleBurst, ParticleBlockBreak, CameraShake, CameraCut, CameraSwitch, UISetItems, SaveSet, SaveGet, SaveDelete, SaveSlot, Tags, HasTag, AddTag, RemoveTag, Children, Has.
  • burrow test on a Go game builds once and runs --runs times under different GOMAXPROCS, requires identical StateHash (each run verifies its own journal replay), honours --go-tests and rejects --parity with a clear message.
  • burrow gen writes burrow_gen.go into the package that is already in scripts/<name>/ (it used to force package main and break a library package).
  • One engine version: project.EngineVersion is a variable set with -ldflags (like internal/game.Version), the MCP servers report it, scripts/dist.sh sets both; a test keeps them equal to the latest released changelog heading.
  • A stale script.hash pinned in a saved scene now says how to fix it in the error.
  • gogame no longer imports the WebAssembly runtime and no longer needs runtime.plugins.scripts: the journaled input snapshot moved to input/inputsnap, the tags component to scene (built in). Component and command names (script.input, script_set_input, tags) and hashes are unchanged; script keeps type aliases.
  • gogame: Parent, ScenePath, FindWith, Field, FieldNum, SetField, BlockEvents, FloodBlocks, SetLevelZone, DeleteLevelZone, ParticleEmit, ParticleStop, FluidAmount, FluidPour, FluidDrain, typed blackboard values; BlockInfo carries ID, Shape and LightLoss.
  • gogame: navigation and AI (NavGoal, NavStop, NavState, NavPath, SetBlackboard, Blackboard, DeleteBlackboard, NavSensed).
  • gogame: animation player control (PlayAnim, StopAnim, SetAnimSpeed, SetAnimParam, TriggerAnim, AnimTime).
  • gogame: block data and scheduled cells (BlockData, SetBlockData, DeleteBlockData, ScheduleBlock, UnscheduleBlock, DueBlocks).
  • gogame: levels (LoadLevel, CurrentLevel, LevelSpawns, LevelZoneAt, LevelSettings).
  • gogame: audio (PlaySound, StopSound, SetSound, SetBusVolume, StopAllSounds, SetListener) and rigid-body queries (RaycastBodies, OverlapBox, ApplyImpulse).
  • gogame: Ctx.SpawnPrefab (name, parent, placement, components) and Ctx.Tolerate (a failed call returns its error without ending the run).
  • gogame: Ctx.SwitchScene; Frame.Alpha, Frame.Find, Frame.VisualSet, Frame.VisualAdd. SceneSwitchRequest moved to app/appctl (alias kept in script).
  • gogame: SpawnNode, Patch (RFC 7386 merge), RemoveComponent, WorldInfo, Light.Level.
  • gogame: Ctx.State, SetState, StateOf, StateBytes, SetStateBytes, DeleteState: the game's own state in a hashed simulation component (snapshots, saves, rollback and replay stay exact). Gameplay concepts (health, hunger, respawn) are deliberately not engine features.

0.6.1 - 2026-11-03

2026-11-03

Simulation rate and scripts#

  • runtime.tick_rate can be 20, 30, 40 or 60; journals record it and refuse a replay at another rate.
  • runtime.physics_substeps refines physics inside a tick without raising the gameplay rate.
  • Scripts get TickRate, TickDt, AfterSeconds and EverySeconds.
  • Seq writes "wait, do, wait until" steps without a hand-made state machine.
  • RootPredict adds root-motion dashes to the client prediction.
  • Child nodes can carry root.move too.

Script debugger#

  • Break, BreakIf and host breakpoints stop the simulation at the end of the tick, with the script's State, Props and host calls.
  • The editor pauses on a stop; Step runs one tick; editor_script_debug does the same for agents.
  • go test -tags slow ./cmd/burrow now builds and runs every script template.

Templates#

  • The platformer, topdown strategy, survival and physics puzzle templates build again.

Root motion#

  • A clip track root.move walks a character through physics.character, so collisions still apply.
  • The velocity is local to the node and rotated by its yaw; it stops when the clip ends or is stopped.

Graphics settings#

  • The shader level can change while the game runs, with no restart.
  • Every part of a level is also a setting of its own, such as bloom, ao, god_rays or shadow_taps.
  • Settings sit on top of the level's preset and survive a level change.
  • runtime.shaders and runtime.graphics in vox.project set them at start.
  • Scripts call SetShaders, SetGraphics, SetGraphicsOn and ResetGraphics.
  • The editor has a Shaders entry in the View menu, a Graphics section in Preferences and the editor_graphics tool.
  • Each change drains the GPU and rebuilds the post pipeline, so expect one frame hitch.

Frame visuals#

  • New components visual.spring, visual.sway and visual.bind animate what is drawn at the screen rate.
  • They can drive position, rotation, scale, lights, shader parameters, the field of view and game UI numbers.
  • They never enter the StateHash and never run on a server.
  • They exist only when a scene uses one or runtime.plugins.visual is true, so other projects keep their hashes.
  • A script can export OnFrame to write the same targets every frame (frame scripts).
  • burrowsdk.Spring is the same spring in simulation time, for gameplay that needs the value.
  • A game UI number can be bound with ui.<key>.
  • See frame visuals.

Rendering#

  • Nodes moved by scripts or physics now glide between ticks instead of jumping 20 times a second.
  • Meshes, sprites, voxel models and point lights are interpolated; teleports and new nodes are not.

Fixes from game feedback#

  • The script SDK builds against the kit again: it no longer imports an engine package the kit does not ship.
  • anim.player clips play in the game, not only in the editor (runtime.plugins.anim, on when a scene uses it).
  • An unknown key in vox.project names its block and the keys valid there.
  • A spawned prefab keeps its root's scale, and a prefab path without a name gives a valid node name.
  • A scene with a bare prefab.instance link gets the prefab's nodes in the game.
  • nav.agent gets feet and face for creatures without physics.character.

Gameplay#

  • The first-person arm no longer shakes while walking; fp_sway and fp_bob tune it.
  • A project block held in hand shows its textures, and a script can set the local player's held block.
  • character supports quadrupeds: four legs, tail, jaw and their own gaits.
  • runtime.vox_front: "magicavoxel" makes render.voxmodel face the same way as characters; new projects use it.
  • The player climbs ladders and vines, collides with bodies and creatures, and takes knockback from player.impulse.
  • Scripts get physics contacts with OnContact.
  • Blocks can opt into random ticks (random_tick) for crops, grass and leaves.
  • A truncated scene search now reports it.
  • Block textures can animate.
  • Lava flows with runtime.plugins.lava.

Worlds#

  • Creating or opening a world, or going back to the title, keeps the window open instead of closing and reopening it.
  • A loading screen covers the frame and holds the simulation until the terrain around the player is loaded.

Character#

  • recolor on render.voxmodel and character makes colour variants of one .vox without a new file, with colour rows in the inspector.
  • character.variant picks a layer set of a layered model, so accessories need no copy of the animal.
  • The character editor preview is drawn by the GPU at full resolution and every frame, no longer pixelated.
  • Right drag orbits, middle drag pans, the wheel zooms smoothly and F frames the character.
  • The particle preview is drawn by the GPU at the panel's size, runs live instead of replaying at 15 Hz, and orbits and zooms.
  • The camera editor shows the world through the rig with the GPU, at full resolution.
  • The game UI designer draws the screen as vectors at any zoom, so text and edges stay sharp.
  • The character component has fp_offset, fp_rot and fp_scale to place the first-person arm and held object.
  • The component has held_model and held_scale to hold any .vox prop instead of a block.
  • A custom .vox model with an arm_r part is drawn as the first-person arm.

0.6.0 - 2026-11-03

2026-11-03

Everything in a scene is an entity, with shaders and materials, per-world voxel size and micro-voxels.

Breaking changes#

  • audio_play, particle_burst and fx_shockwave now need an emitter entity.
  • Offsets replace absolute positions in those three calls.
  • audio_music now returns DENIED.
  • The SDK calls PlayOn, ParticleBurstOn, ParticleBlockBreakOn and Shockwave(emitter, ...) replace the old audio and particle calls.
  • See script/ABI.md for the removed SDK names.

First public version of Burrow: a deterministic voxel game engine in Go, with an editor, scripting, a Vulkan renderer and an interface made for AI agents. Early version, MIT licensed.

Engine#

  • Same seed and same inputs always give the same world, so any session can be replayed (burrow test).
  • Voxel worlds with biomes, rivers, mountains and caves, plus physics, pathfinding, particles, weather and water.
  • Scene tree with prefabs and saves, a game UI toolkit and six camera types (first and third person, top-down, isometric, side-scroller, cinematic).
  • Nine project templates: sandbox, builder, scripted, platformer, physics puzzle, top-down strategy, survival, models, empty.

Rendering#

  • Vulkan renderer with quality levels from off to ultra: sky, clouds, shadows, ambient occlusion, bloom, water reflections, rain, snow and storms.
  • Anti-aliasing and upscaling (FXAA, SMAA, TAA, FSR 1 and 2) and optional ray tracing.
  • A CPU renderer makes the same images without a window or GPU, for tests and screenshots.

Editor and tools#

  • burrowedit: viewport, hierarchy, inspector, asset browser, profiler, terrain tools, undo and redo, Play mode and built-in tutorials.
  • burrow command line: new, run, edit, test, build, script, assets, doctor, docs.
  • Everything the editor does also works headless over MCP and a JSON CLI.

Scripting#

  • Scripts are written in Go, compiled to WebAssembly, or built as visual graphs with no code.
  • They run inside the simulation, so they replay like everything else.

Hub and distribution#

  • Burrow Hub manages projects and engine versions, opens the editor, plays and exports.
  • Update checks are optional and only signed manifests are accepted.
  • No telemetry is sent.
  • A Windows x64 download holds the editor, Hub, command line, script SDK, docs and templates.
  • A website hosts the documentation, news and this changelog.

Known limits#

  • This is an early version and the API may change.
  • Windows builds are untested on real hardware and unsigned, so SmartScreen may warn.
  • Windowed use is supported on macOS Apple silicon only.
  • There is no multiplayer yet.
  • Textures are not animated, and blocks added after Minecraft 1.16 use flat colours.
