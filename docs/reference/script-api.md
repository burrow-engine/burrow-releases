# Script API

> Generated by `make docs-gen` from the source code. Do not edit this page by hand: change the code or its doc comments and regenerate.

Scripts are WebAssembly modules run by the deterministic scripting host. They talk to the engine through the **host functions** below (imported from the `vox` module; the module name predates the engine rename and is part of the ABI) and, for Go scripts, through the **SDK** that wraps them. The full execution model is in [scripting.md](../scripting.md).

```go

```

OnBlockTick registers fn for the scheduled cells of block name that are due (topic block.tick/<name>; an empty name receives every block.tick). fn gets the cells of one batch (about 1,000), in due order: a world with thousands of machines costs the script one call per batch, and only for the machines that are due. ```go


OnBlockRandomTick registers fn for the random ticks of block name (topic block.random/<name>; an empty name receives every block.random). Each tick the host draws a few random cells of every loaded chunk (runtime.random_tick_rate, default 24 per 32^3 chunk, like Minecraft's 3 per 16^3 section) and sends the ones holding a block declared "random_tick": true in runtime.custom_blocks, in batches like OnBlockTick (cells in chunk order, a cell drawn twice appears twice). Use it to grow crops, spread grass or decay leaves. The draw depends only on the seed, the tick and the chunk, so replays agree.

```go

```

BlockSchedule makes the cell, which must hold a block, a scheduled machine: it arrives in OnBlockTick delay ticks after the next tick (0 = the next tick) and then every `every` ticks (0 = once). A schedule replaces the previous one of the cell; it is cancelled when the cell holds another block, or when BlockUnschedule or DeleteBlockData is called.


BlockUnschedule cancels the schedule of the cell; its data stays.

```go

```

Names are registry names without [props].
