Script API#

Generated by make docs-gen from the source code. Do not edit this page by hand: change the code or its doc comments and regenerate.

Scripts are WebAssembly modules run by the deterministic scripting host. They talk to the engine through the host functions below (imported from the vox module; the module name predates the engine rename and is part of the ABI) and, for Go scripts, through the SDK that wraps them. The full execution model is in scripting.md.

BlockBase returns the registry name of a block without its state: "mymod:belt[facing=east]" gives "mymod:belt".

BlockProp returns the value of a state property of a block name ("east" for "mymod:belt[facing=east]" and "facing"), or "" when the block has no such property (the default state of a block with facing is named without props and faces north).

OnBlockChange registers fn for every change of a voxel (topic block.change). Call it from init().

OnBlockSet registers fn for the voxels that now hold block name (topic block.set/<name>).

OnBlockBreak registers fn for the voxels that held block name and do not any more: the block was broken or replaced (topic block.break/<name>). ev.Data is the data the cell lost.

func OnBlockUse(name string, fn func(self Entity, ev BlockEvent))

OnBlockUse registers fn for a player's right click on block name, when the block is declared interactive in the project's block file ("interact": true). An empty name receives every use (topic block.use).

func OnBlockTick(name string, fn func(self Entity, cells [][3]int))

OnBlockTick registers fn for the scheduled cells of block name that are due (topic block.tick/<name>; an empty name receives every block.tick). fn gets the cells of one batch (about 1,000), in due order: a world with thousands of machines costs the script one call per batch, and only for the machines that are due. The batch is binary, so it costs a few instructions per cell. Arm a cell with BlockSchedule; read the machines with BlockDataMany and write them back with BlockDataApply.

func OnBlockRandomTick(name string, fn func(self Entity, cells [][3]int))

OnBlockRandomTick registers fn for the random ticks of block name (topic block.random/<name>; an empty name receives every block.random). Each tick the host draws a few random cells of every loaded chunk (runtime.random_tick_rate, default 24 per 32^3 chunk, like Minecraft's 3 per 16^3 section) and sends the ones holding a block declared "random_tick": true in runtime.custom_blocks, in batches like OnBlockTick (cells in chunk order, a cell drawn twice appears twice). Use it to grow crops, spread grass or decay leaves. The draw depends only on the seed, the tick and the chunk, so replays agree.

func BlockSchedule(x, y, z, delay, every int) error

BlockSchedule makes the cell, which must hold a block, a scheduled machine: it arrives in OnBlockTick delay ticks after the next tick (0 = the next tick) and then every every ticks (0 = once). A schedule replaces the previous one of the cell; it is cancelled when the cell holds another block, or when BlockUnschedule or DeleteBlockData is called.

func BlockUnschedule(x, y, z int) error

BlockUnschedule cancels the schedule of the cell; its data stays.

func BlockFlood(x, y, z int, through, ends []string, max int) (cells []FloodCell, truncated bool, err error)

BlockFlood returns the network connected to (x, y, z): the blocks named in through (cable, pipe, belt: listed and expanded) and ends (machine, tank: listed, not expanded) reachable from it by shared faces, breadth first, at most max cells (1..60,000). The start cell must itself be one of them. truncated reports a network larger than max. One host call walks the whole network natively, which is what makes cable and pipe networks of thousands of blocks affordable: the script then balances the machines it found with BlockDataApply. Names are registry names without [props].

func BlockData(x, y, z int) (data string, ok bool, err error)

BlockData returns the data of the cell (ok false when it has none). It sees this call's own writes.

func SetBlockData(x, y, z int, data string) error

SetBlockData stores the data of the cell, which must hold a block (INVALID for air, LIMIT above 16 KiB).

func DeleteBlockData(x, y, z int) error

DeleteBlockData removes the data of the cell.

func BlockDataJSON(x, y, z int, v any) (ok bool, err error)

BlockDataJSON decodes the JSON data of the cell into v (ok false when it has none).

func SetBlockDataJSON(x, y, z int, v any) error

SetBlockDataJSON stores v, encoded as JSON, as the data of the cell.

func BlockDataMany(cells [][3]int) (data []string, ok []bool, err error)

BlockDataMany returns the data of up to 4,096 cells with one host call, in the order asked; ok[i] is false when cell i has none. It sees this call's own writes. It is the way to read the machines that OnBlockTick just reported. The exchange is binary (no JSON in the guest), a few instructions per cell.

func BlockDataIn(min, max [3]int, limit int) (cells []BlockCell, more bool, err error)

BlockDataIn lists the cells with data inside the inclusive box min..max, sorted by (x, y, z), at most limit of them (0 = the host maximum, 4096). more reports further cells beyond the limit (or beyond what fits one answer, about 56 KiB). It reads the committed state: this call's own writes are not in it.

func BlockDataApply(ops []BlockDataOp) error

BlockDataApply applies up to 4,096 operations in order with one host call: the way a script updates many machines in a tick without spending its call budget (each operation still counts as a block edit). The exchange is binary, a few instructions per operation.
