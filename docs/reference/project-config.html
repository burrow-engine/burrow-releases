Project file#

Generated by make docs-gen from the source code. Do not edit this page by hand: change the code or its doc comments and regenerate.

A project is a folder with a vox.project manifest (JSON). The sections below list every key. Keys under runtime configure burrowplay, the exported game and the editor's Play mode. Everything is additive: a missing key keeps the default in the description, and unknown keys are rejected with a message naming the valid ones.

runtime#

Runtime is the optional "runtime" section of vox.project: how the game runner (burrowplay) builds the app. Zero values select the defaults noted.

keytypedescription
runtime.titlestringwindow title (default: project name)
runtime.widthintwindow width (1280)
runtime.heightintwindow height (720)
runtime.radiusintterrain load radius in chunk columns (8)
runtime.modestring"fly" (default) or "walk"
runtime.start*[3]float64player start (feet); default above terrain at 0,0
runtime.yawfloat64start yaw, degrees
runtime.pitchfloat64start pitch, degrees
runtime.player_prefabstringPlayerPrefab is the prefab the player is spawned from when the scene has no game.mode: "builtin:player.prefab" (the default) or a project .prefab, usually a variant (an instance of the built-in one with overrides).
runtime.seeduint64world seed (default: the .voxworld seed, else 1)
runtime.worldstring.voxworld overlay loaded at start
runtime.texture_packstringTexturePack selects the block textures: "default" (embedded Pixel Perfection CE, may be absent), "pixelperfection" or "none" (flat colours).
runtime.blocksstringBlocks selects the block registry. "shapes" (the default, and the only supported registry) is the core blocks, the full-cube Minecraft block set of package blockset and the non-cubic shapes of package shape (slabs, stairs, plants, ...). New projects are created with "shapes" and "pixelperfection".
runtime.custom_blocksstringCustomBlocks is the project's own block file (JSON, project relative, e.g. "data/blocks.json"): its blocks are appended to the registry after every built-in block, in file order, and can carry textures, a palette entry and a right-click interaction (package blockset, Custom; docs/blocks.md "Project blocks"). Absent = no project blocks.
runtime.block_packs[]stringBlockPacks enables optional block content packs on top of the neutral engine set, in order (blockset.PackNames: "minecraft" is the full Minecraft catalog, 338 full cubes and about 230 shaped items, which pairs with the "pixelperfection" textures). Ignored when BlockRegistry is set. Before 0.7 that catalog was built in, so burrow migrate enables it for older projects.
runtime.block_registrystringBlockRegistry is a project folder (e.g. "blocks") holding the project's own copy of the block registry: blocks.json and shapes.json in the format of the engine's block files, in id order. When set it REPLACES the engine's blocks and every pack, so the ids and properties of the project's blocks no longer depend on the engine version. burrow blocks export writes it and burrow new creates it; runtime.custom_blocks are still appended after it. See docs/blocks.md "Project registry".
runtime.itemsstringItems is the project's item registry file (JSON, project relative, e.g. "data/items.json"): the items scripts name and carry, with stable ids (package itemset, docs/items.md). Item 0 is the empty stack; the engine provides identity and stacks only, the mod writes recipes, inventories and dropped items. Absent = no items.
runtime.script_limits*ScriptLimitsScriptLimits raises (or lowers) the limits of the scripting host for this project: gas per call, guest memory and the host call budgets, which a mod with thousands of machines needs more of. A zero field keeps the default. The values are part of the simulation identity: a replay or a multiplayer peer must use the same project file. See docs/scripting/09-errors-and-limits.md.
runtime.hotbar[]stringHotbar names the blocks of the nine hotbar slots at start (registry names, "" = leave the slot as it is); it is how a project puts its own blocks in the player's hands.
runtime.aastringAA, Upscale and RenderScale configure the anti-aliasing and the upscaler of the HDR shader levels (additive; "" = the shader level's preset, no upscaler, native resolution): "off|fxaa|smaa|taa", "off|fsr1|fsr2|dlss|xess" and "native|quality|balanced|performance" or a scale 0.5..1 / 50..100. burrowplay's -aa, -upscale and -render-scale flags override them. See docs/anti-aliasing.md.
runtime.upscalestring
runtime.render_scalestring
runtime.shadersstringShaders is the shader level at start ("off|low|medium|high|ultra"; "" = BURROW_SHADERS, else medium) and Graphics are individual graphics settings on top of it (render.GraphicsNames, e.g. {"bloom": false, "god_rays": 32}; a switch is true/false or 0/1). burrowplay's -shaders flag overrides Shaders. Both can change while the game runs (the SetShaders and SetGraphics script calls, the editor's View menu). See docs/rendering.md.
runtime.graphicsrender.GraphicsOverrides
runtime.distortionDistortionSettingDistortion is the strength of the air distortion (heat haze, shock waves) of the HDR shader levels medium and up: true / "on" (default), false / "off", or a multiplier 0..4 (JSON number or string). burrowplay's -distortion flag overrides it. See docs/rendering.md.
runtime.tick_rateintsimulation ticks per second: 20 (default), 30, 40 or 60
runtime.physics_substepsintPhysicsSubsteps is how many sub-steps the physics runs inside each tick (0 = the engine defaults: 8 for rigid bodies, the walker's own for characters; 1..32). More sub-steps give finer contact and movement at the cost of CPU, without raising the rate of the scripts and gameplay (tick_rate does that). See docs/physics.md.
runtime.random_tick_rateintRandomTickRate is the cells drawn per loaded chunk (32^3) and tick for random block ticks (0 = 24, like Minecraft's 3 per 16^3 section; 1..4096). Only blocks with "random_tick": true in runtime.custom_blocks receive them. See docs/blocks.md.
runtime.hud*boolHUD draws the sandbox overlay of the voxel renderer (crosshair, hotbar, frame statistics). Default: on, except when plugins.controller is false (a game without the first-person player has no use for it).
runtime.cursorstringCursor is "" or "captured" (the mouse is grabbed: look around) or "free" (visible; the pointer position is reported to the input map as the mouse_pos binding, for strategy-style games).
runtime.vsync*booldefault true
runtime.generator*GeneratorGenerator selects the terrain base layer (default heightmap with trees).
runtime.particle_overridesmap[string]stringParticleOverrides replaces builtin particle effects by project files: "builtin:debris" -> "assets/particles/debris.particles.json".
runtime.plugins*PluginsPlugins switches runtime plugins on or off. Only render, input, controller, character and fine_water default on; every other plugin adds simulation state or components and is off unless the project enables it (PluginTable, docs/reference/project-config.md).
runtime.levels*LevelsLevels and Saves configure the level and save plugins (see Plugins.Levels, Plugins.Saves).
runtime.saves*Saves
runtime.camera*CameraCfgCamera and GameUI configure the camera and game UI plugins (see Plugins.Camera, Plugins.GameUI).
runtime.gameui*GameUICfg
runtime.lobby*lobby.ConfigLobby installs the multiplayer lobby (package net/lobby, docs/lobby.md): players, teams, colours, ready flags, game settings, a countdown and the match results as hashed simulation state of the session. Present = on (it also needs plugins.net: true). The whole section is part of the session configuration hash.
runtime.net_modelstringNetModel chooses the multiplayer network model: "lockstep" (the default: every peer runs the whole simulation on the same ordered commands, docs/networking.md) or "replicated" (the server alone runs the simulation and streams to each client the chunks and entities around its player: persistent public servers, docs/replication.md). Part of the session configuration hash: server and clients must agree.
runtime.proximity_chatfloat64ProximityChat makes multiplayer chat local: a player's line reaches only the players within this many voxels (in the replicated model: of the sender's interest center; in lockstep: of its avatar node "avatar_<id>" or its spawn point). 0 or absent = everyone hears everyone. Lines of the server always reach everyone.
runtime.audio*AudioCfgAudio configures the user sound pack and the music scheduler (additive; see docs/audio.md, "Sound packs").
runtime.voice*voicecfg.ConfigVoice configures proximity voice chat (package voice, docs/voice.md): radius, push_to_talk or voice_activation, the push-to-talk action and key, max_speakers, channels, gains. Needs plugins.voice: true. Frame domain: not part of the session configuration hash (the server enforces the radius itself).
runtime.weatherboolWeather turns the deterministic weather simulation on (package weather; default off so existing projects keep their StateHash); Seasons adds the seasonal temperature cycle.
runtime.seasonsbool

runtime.script_limits#

ScriptLimits is the "runtime.script_limits" section; every field is optional (0 = the default of script.Config).

keytypedescription
runtime.script_limits.gasint64Gas is the deterministic instruction budget of one guest call (default 50,000,000, at most 2,000,000,000). A mod whose manager script walks thousands of machines in one call needs more. Exhaustion is a fault, counted like any other.
runtime.script_limits.memory_pagesuint32MemoryPages caps guest linear memory in 64 KiB pages (default 512 = 32 MiB, at most 4096; a Go guest needs about 180 pages to start). Raise it for scripts that hold large tables of machines.
runtime.script_limits.max_faultsuint32MaxFaults is the number of faults before a script is disabled (default 3, at most 1000).
runtime.script_limits.keep_memoryboolKeepMemory gives every script node its own guest instance whose memory is not reset between calls, so ordinary Go globals and heap persist across ticks. Single player only (rejected with runtime.plugins.net, a replicated net_model or a dedicated server); a fault, a hot reload or a save load restarts the memory from the module image. See docs/scripting/02-execution-model.md.
runtime.script_limits.per_script*ScriptBudgetPerScript is the host call budget of one script transaction, every script separately (default 1,000 calls, 1 MiB, 32 spawns, 4,096 voxel edits, 64 events).
runtime.script_limits.per_tick*ScriptBudgetPerTick is the host call budget of all scripts together in one tick (default 200,000 calls, 64 MiB, 1,024 spawns, 262,144 voxel edits, 4,096 events).

runtime.generator#

Generator configures the base terrain. Kind "heightmap" (default) uses Base/Amp/Scale/Octaves/SeaLevel/Caves/Trees, kind "flat" uses SurfaceY/Depth. Kind "empty" is all air. Kind "biomes" is generator v2 (biomes, rivers, mountains, caves; see docs/worldgen.md): it uses SeaLevel (0 = 36), Scale (horizontal size factor, 0 = 1), Amp (vertical relief in percent, 0 = 100), Caves and Trees.

keytypedescription
runtime.generator.kindstring
runtime.generator.baseint
runtime.generator.ampint
runtime.generator.scalefloat64
runtime.generator.octavesint
runtime.generator.sea_levelint
runtime.generator.cavesbool
runtime.generator.trees*booldefault true
runtime.generator.surface_yint
runtime.generator.depthint
runtime.generator.voxel_sizefloat64VoxelSize is the voxel edge in metres: 1 (default), 0.5, 0.25 or 0.125. Every other size in this section (base, amp, scale, sea_level, surface_y, depth) stays in metres, so a smaller voxel gives the same landscape in more detail.
runtime.generator.texture_scalestringTextureScale is "voxel" (default: one block texture tile per voxel) or "metre" (one tile per metre, so a 0.25 m voxel keeps the texel density of a 1 m one). Render only; no effect with 1 m voxels.

runtime.plugins#

Plugins toggles runtime plugins; nil means the default of PluginTable (off for everything that adds simulation state).

keytypedescription
runtime.plugins.physics*bool2D physics and the physics.character controller; off by default
runtime.plugins.fluid*boolwater flow (package fluid); off by default, inert until water is disturbed
runtime.plugins.fine_water*boolFineWater selects the adaptive fine water (docs/water-fine.md) instead of the coarse 8-level automaton; on by default (only read when fluid is on).
runtime.plugins.lava*boolLava makes lava flow (docs/water-physics.md "Lava"): the blocks lava and lava_1..lava_3 are registered and spread from a source at a third of the speed of water. Off by default (it changes StateHash); needs fine_water off.
runtime.plugins.swell*SwellCfgSwell makes the water surface rise and fall with travelling waves (package swell): the buoyancy of physics3d bodies reads it and the renderer draws the same waves. Needs Physics3D; absent or amp 0 = a flat surface.
runtime.plugins.nav*boolNav installs navigation and AI (package nav: nav.agent, ai.brain, ai.perception components, the "nav" system and the nav_set_goal/nav_stop commands; behaviour trees load from <name>.bt.json in the project). Off by default; registering its components and state changes StateHash. See docs/navigation-ai.md.
runtime.plugins.net*boolNet installs the multiplayer player registry (package net/netsim, docs/networking.md): the net_player_* commands and the hashed list of players. Off by default: the registry is simulation state. The network itself (burrow serve, burrowplay -connect, the Hub) works on any project.
runtime.plugins.blocks*boolBlocks installs block logic (package blocklogic): per-cell block data for scripts (the "block entity"), the block change and block use events delivered to scripts, and the journaled block_data_* / block_use commands. Off by default: it is simulation state and changes StateHash. See docs/blocks.md "Block logic".
runtime.plugins.scripts*boolWebAssembly scripting; off by default, required when scripts are listed
runtime.plugins.input*boolinput map and journaled input; on by default
runtime.plugins.controller*boolfirst-person controller and sandbox HUD; on by default
runtime.plugins.render*boolwindow + renderer (windowed runs only); on by default
runtime.plugins.character*boolCharacter is the player avatar (windowed runs; on by default, with the controller). The character scene component is registered when it is explicitly true or when the default scene uses it: registering a component changes StateHash, so projects without characters keep their hashes.
runtime.plugins.visual*boolVisual registers the frame visual components visual.spring, visual.sway and visual.bind (docs/visual-effects.md). Registering a component changes StateHash, so they are registered only when this is true or a scene or prefab of the project uses one; other projects keep their hashes. They never run on a server and never enter the hash themselves.
runtime.plugins.anim*boolAnim installs keyframe animation (package anim; docs/animation.md): the anim.player component, its sim system and the project's .anim clips. Registering the component changes StateHash, so it is registered only when this is true or a scene or prefab of the project uses anim.player; other projects keep their hashes.
runtime.plugins.audio*boolAudio is the audio subsystem (package audio; docs/audio.md): the mixer, the sandbox ambience (windowed runs) and the audio_source / audio_listener scene components. Off by default; registering the components changes StateHash. A default scene that uses an audio component registers them too (silent, null backend) unless this is explicitly false; the ambience and music play only when this is true.
runtime.plugins.particles*boolParticles is the particle system (package particles; docs/particles.md): the particle_emitter scene component, the per-frame simulation and the GPU / CPU renderers. Off by default; registering the component changes StateHash. A default scene that uses the component registers it too unless this is false.
runtime.plugins.physics3d*boolPhysics3D installs the rigid-body engine (package physics3d, docs/physics.md): rigid bodies, voxel bodies, joints and destruction. Off by default; registering its components and state changes StateHash.
runtime.plugins.levels*boolLevels installs fixed levels (package level; docs/levels-saves.md): the journaled level_load command, trigger zones, the level manager and the level_* script functions. Off by default; it adds simulation state and changes StateHash. Configure with runtime.levels.
runtime.plugins.saves*boolSaves installs the save system (package save): slots, the game key/value data scripts use (save_set / save_get), autosave and the save_* script functions. Off by default; it adds simulation state. Configure with runtime.saves.
runtime.plugins.camera*boolCamera installs the camera rigs (package camera; docs/cameras.md): the camera_rig scene component and the rig controller that drives the view. Frame domain; off by default (the component changes StateHash). Configure with runtime.camera.
runtime.plugins.gameui*boolGameUI installs the game UI (package gameui; docs/game-ui.md): .ui.json screens, HUD and menus, journaled UI events. Off by default (the event inbox is simulation state). Configure with runtime.gameui.
runtime.plugins.voice*boolVoice installs proximity voice chat (package voice; docs/voice.md): microphone capture in windowed runs, spatialised playback, push-to-talk (V, or a push_to_talk action of the input map) and the voice_talking HUD values. Off by default (it opens the microphone); frame domain, never simulation state. Needs net. Configure with runtime.voice.
runtime.plugins.distortion*boolDistortion is the air distortion (package distortion; docs/rendering.md): heat haze above hot blocks and shock waves (frame domain, on by default at shader level medium and up) and the fx.distortion scene component. The component changes StateHash, so it is registered only when this is true or a scene of the project uses it; false turns the whole effect off. Strength: runtime.distortion.
