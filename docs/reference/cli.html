Command line#

Generated by make docs-gen from the source code. Do not edit this page by hand: change the code or its doc comments and regenerate.

Three programs ship with the engine: burrow (the project tool that drives the others), burrowplay (the game runner) and burrowedit (the editor). Flags may be written with one or two dashes. burrow <command> --help prints the same usage text as this page.

burrow run#

Play a project (burrowplay).

usage: burrow run [dir] [--validate] [--json] [-- burrowplay flags]

Plays the project in dir (default .): builds stale scripts, then starts burrowplay
with the MoltenVK environment set explicitly (SIP strips DYLD_* through /bin/sh,
so Burrow passes it to the child itself).

A Go game (root main.go importing burrow-engine/gogame) runs as "go run . -dir <dir>" instead; flags after -- go to it.
Flags after -- go to burrowplay, e.g.  burrow run -- -shot out.png -frames 60
or  burrow run -- -headless -ticks 200 -hash

flags:
  --validate   enable the Vulkan validation layer (VK_LAYER_PATH is set)
  --no-scripts do not rebuild scripts first
flagtypedefaultdescription
-no-scriptsboolskip building scripts
-validateboolvalidation layer

burrow serve#

Run a dedicated multiplayer server and print the join link.

usage: burrow serve [dir | game.voxpak] [flags]

Runs a dedicated multiplayer server for a project (docs/networking.md). The project must set
runtime.plugins.net to true. The server listens with TLS 1.3 (a self-signed certificate created on first run in
<user config dir>/burrow/server, private key mode 0600), checks that every client runs the same project, engine version
and rules, and prints the join link:

  burrow://host:7777?fp=<certificate fingerprint>&key=<password>

For a server that runs on a real machine (persistent world, autosave, bans, systemd or Docker), use the burrow-server
executable instead (docs/dedicated-server.md).

Give the link to the players (burrowplay -connect <link>, or the Hub). The key is the server password: treat the link as a
secret. Without a password anyone who reaches the port can join.

flags:
  --addr :7777        listen address
  --advertise host:p  the address written in the link (default 127.0.0.1 and the listen port: pass your public name)
  --password text     join key (default: a random one)
  --open              no password
  --max-players N     at most N players (default 16)
  --seed N            world seed (every client must use the same project; the seed is pinned)
flagtypedefaultdescription
-addrstringfmt.Sprintf(:%d, netplay.DefaultPort)listen address
-advertisestringaddress written in the join link
-max-playersintplayer limit
-openboolno password
-passwordstringjoin key
-seeduintworld seed

burrow build#

Pack a project into a single-file game or macOS .app.

usage: burrow build [dir] -o <out> [--app] [--native|--wasm] [--target darwin-arm64] [--burrowplay path] [--no-default-textures] [--no-verify] [--json]
       burrow build [dir] --pak <file.voxpak>

Packs the project into ONE self-contained executable: a copy of the prebuilt
burrowplay with the game archive (.voxpak: vox.project, asset directories, scene,
input map, world overlay, scripts; sorted, SHA-256 per file and overall)
appended. ./game runs with no toolchain and no project directory.

  -o out           output executable (default ./<project name>)
  --app            write a macOS <out>.app bundle INSTEAD of the plain executable (Info.plist, MacOS/<exe>,
                   Resources/game.voxpak, Frameworks/); the archive ships once, in Resources, and the bundle is ad-hoc
                   signed once as a whole (codesign --verify --deep --strict passes);
                   libvulkan.1.dylib and libMoltenVK.dylib (with an ICD manifest) are bundled when found in Homebrew
                   with install_name_tool; otherwise the app needs Homebrew molten-vk and says so when it is missing.
                   The app and the plain executable are ad-hoc signed (codesign -s -): they run on this Mac, but they are
                   NOT notarised. The plain executable has the archive appended after the Mach-O, so strict code-signature
                   validation and Gatekeeper need a proper Developer ID signature and notarisation (use --app for that). A copy downloaded by someone else carries the macOS quarantine flag and Gatekeeper blocks
                   it ("cannot be opened because the developer cannot be verified"): the recipient clears it with
                   xattr -dr com.apple.quarantine <app>, or you sign with a Developer ID (codesign --force --deep --options
                   runtime -s "Developer ID Application: ..." <app>) and notarise (xcrun notarytool submit ... --wait; xcrun stapler staple <app>)
  --pak file       write only the archive
  --target t       only the native target is supported (darwin-arm64 on Apple silicon): burrowplay links
                   cgo (GLFW, Cocoa) and MoltenVK, so cross-compiling needs the target's C toolchain and SDK
  --burrowplay path   burrowplay binary to embed (default: next to Burrow, on PATH, or built from the checkout)
  --no-default-textures
                   embed a burrowplay built with -tags novnr,nopp: the default block textures (Pixel Perfection CE,
                   CC-BY-SA-4.0) are NOT bundled and blocks render flat. Needs the Burrow source
                   checkout (go build); cannot be combined with --burrowplay. Without it, a game that bundles the default
                   textures (runtime.texture_pack is not "none") gets their licence warning on stderr and in the build manifest
  --no-verify      skip the load-and-run check before packing
  --native         link the project's Go scripts into the game executable instead of shipping WebAssembly (like IL2CPP in
                   Unity): faster, no .wasm in the archive, one executable. Compiles a player from the Burrow source
                   checkout (BURROW_ROOT) with the Go toolchain; scripts then run without gas or a memory sandbox, and the
                   editor/mods keep using wasm. burrow test --parity proves both runtimes simulate identically
                   (docs/scripting/15-native.md). BURROW_BUILD_NATIVE=1 makes it the default.
  --wasm           ship the scripts as WebAssembly in the archive (the default); the prebuilt burrowplay is used as is

The build manifest <out>.build.json (also with --app: <out>.app plus <out>.build.json) records the pack hash, the texture bundling decision and the licence warning.
flagtypedefaultdescription
-appboolmacOS .app bundle
-burrowplaystringburrowplay binary
-nativeboollink the scripts natively
-no-default-texturesboolbuild burrowplay with -tags novnr,nopp (no embedded block textures)
-no-verifyboolskip verification
-ostringoutput
-pakstringwrite only the archive
-targetstringtarget (native only)
-wasmboolship the scripts as WebAssembly

burrow test#

Headless project check: load, run, replay, StateHash.

usage: burrow test [dir] [--ticks N] [--runs N] [--parity] [--go-tests] [--json]

Headless health check of the project in dir (default .). No window, no GPU:
  1. load vox.project, the default scene, the world overlay and the input map
  2. build stale scripts and verify every module the project lists
  3. run N ticks (default 200) --runs times (default 3) with GOMAXPROCS = default, 1 and 8;
     the StateHash must be identical every time
  4. check for failed commands and script faults, replay the journal and compare
  5. with --go-tests only: run "go test ./..." in the project when it has its own _test.go files
  6. with --parity only: link the project's scripts natively into a headless runner (the same linking as burrow build
     --native), run it for the same N ticks and require the very same StateHash as the WebAssembly run above; also runs
     the natives with BURROW_NATIVE_DEBUG=1, which faults any script that keeps state in package-level variables
Prints the StateHash; exit 1 on any problem.
A Go game (root main.go importing burrow-engine/gogame) runs "go run . -dir <dir> -headless <ticks>" and reports its JSON line.

flags:
  --ticks N      fixed ticks per run (1 s = runtime.tick_rate ticks, 20 by default)
  --runs N       number of runs (default 3)
  --parity       prove native == wasm: needs the Burrow source checkout (BURROW_ROOT) and compiles the engine once
  --go-tests     also run the project's own Go tests (go test ./...). WARNING: that compiles and runs the project's Go
                 code natively and UNSANDBOXED with your user's permissions; use it only on projects you trust
                 (scripts that run inside Burrow are sandboxed, go test code is not; see docs/security.md)
  --json         machine-readable report

Note: building the project's script sources (scripts/*/*.go) to WebAssembly also runs the Go toolchain on project code
(compile time only; the resulting wasm runs sandboxed). Only test projects you trust.
flagtypedefaultdescription
-go-testsboolalso run the project's Go tests (unsandboxed)
-parityboolnative scripts must produce the same StateHash as wasm
-runsint3runs
-ticksint200ticks per run

burrow gen#

Write typed constants for the project's action, asset, UI and node names.

usage: burrow gen [dir] [--json]

Writes burrow_gen.go ("Code generated by burrow gen. DO NOT EDIT.") into every scripts/<name>/ package, and next to
main.go when the project root is a Go game (package main). It holds typed constants for the names a project is wired
with, so a typo is a compile error instead of a runtime surprise:

  Action<Name>   input actions (input map)        Scene<Name>   scenes (.voxscn)
  Prefab<Name>   prefabs (.prefab)                UIFile<Name>  UI documents (.ui.json)
  Model<Name>    models (.vox .glb .gltf .obj)    Sound<Name>   sounds (.wav .ogg .mp3 .flac)
  Script<Name>   wasm modules (.wasm)             Screen<Name>  UI screens
  UIKey<Name>    UI value keys (bind, {text})     UIAction<Name> UI action strings (ui:show:pause)
  Node<Name>     node names in scenes             Block<Name>   project blocks (runtime.custom_blocks)

Output is sorted and gofmt'd; a file is only rewritten when its content changed. burrow script build and
burrow new run it first. burrow check validates the string literals scripts pass to the SDK against the same names.

dir defaults to the current directory.

burrow check#

Fast static validation of a project: JSON, asset paths, names used by scripts.

usage: burrow check [dir] [--json]

Fast static validation of the project in dir (default .): no ticks, no build, no GPU.
  - every JSON file (vox.project, scenes, prefabs, UI documents, input map, *.json) parses
  - scene script modules are listed in vox.project "scripts"; scenes, prefabs, UI documents, models and sounds
    that scenes, prefabs, UI documents and vox.project point to exist
  - ui:show / ui:hide / ui:toggle actions name a screen that exists
  - string literals scripts pass to the SDK exist in the project: Action*, SceneLoad, SceneSwitch, Spawn,
    UIShow, UIHide, UIToggle, UISetNum, UISetStr, UISetBool, UISetItems, FindByName, PlayOn, BlockByName
    (scripts/*/*.go and the root *.go files)
Unknown names are reported with the closest match. Use the generated constants (burrow gen) to avoid them.

Output is one problem per line, file:line: message (hint). With --json:
  {"ok":bool,"problems":[{"file","line","msg","hint"}]}
Exit 0 when clean, 1 on any problem. (The headless run is burrow test.)

burrow config#

Get or set a vox.project value by dotted path.

usage: burrow config get <key> [-C dir] [--json]
       burrow config set <key> <value> [-C dir] [--string] [--append] [--json]
       burrow config rm <key> [-C dir] [--json]

Reads or edits vox.project by dotted path, without hand-written JSON and without shell quoting trouble.

  burrow config get runtime.plugins.controller
  burrow config set runtime.plugins.controller false
  burrow config set runtime.title "My Game"        (a bare word or text that is not JSON is a string)
  burrow config set runtime.start [3.5,9,8.5]       (JSON arrays and objects work; on Windows cmd use @- and stdin)
  burrow config set runtime.generator.kind flat
  burrow config get runtime                          (a whole section, as JSON)

key     dotted path; an array element is a number or brackets: runtime.camera.rigs.0.name, a.b[2]
        a trailing [] (or --append) appends to the array: config set a.b[] 5
rm      removes an object key or an array element: config rm a.b[2]
value   JSON (true, 12, [1,2], {"a":1}), otherwise a string; "@-" reads the value from stdin
-C dir  project directory (default .)
--string  force the value to be a string ("12" stays text)
--append  append the value to the array at key

set edits the file in place: key order, comments-free formatting and every untouched line stay as they are. The
result is validated with the project loader (unknown fields, ranges, plugin names) before an atomic write; on an
error the file is not touched.
flagtypedefaultdescription
-Cstring.project directory
-appendboolappend to the array
-stringbooltreat the value as a string

burrow blocks#

List block packs; keep a copy of the block registry in the project.

usage: burrow blocks packs
       burrow blocks export [dir] [--folder blocks] [--pack NAME]... [--force] [--json]

packs    lists the optional block packs this engine carries (for runtime.block_packs).
export   writes the project's OWN COPY of the block registry into dir/<folder> (blocks.json and shapes.json, one block per
         line, in id order) and sets runtime.block_registry to that folder. From then on the project's block ids and
         properties come from those files, not from the engine, so an engine update can never renumber or change them.

         --pack NAME   include a pack in the copy (repeatable; default: the packs in runtime.block_packs, else none).
                       "minecraft" is the full Minecraft catalog (338 cubes, about 230 shaped items).
         --folder DIR  project folder for the copy (default "blocks").
         --force       overwrite an existing copy (the copy is the project's own: exporting again from the engine
                       replaces your edits and can renumber blocks, so it is refused unless you ask).

Maps (.voxworld) are matched to the registry by block name, so a map made with another registry still opens as long as every
block it uses exists. burrow new creates this copy for every new project. dir defaults to the current directory.
flagtypedefaultdescription
-folderstringblocksproject folder of the registry copy
-forcebooloverwrite an existing registry copy
-packvalueinclude a block pack in the copy (repeatable)

burrow scene#

Read and edit scene (.voxscn) components from the shell.

usage: burrow scene get <scene.voxscn> [node [component]] [--json]
       burrow scene set-component <scene.voxscn> <node> <component> <json | field=value...> [--replace]
       burrow scene rm-component <scene.voxscn> <node> <component>

Reads and edits a .voxscn without hand-written JSON. A node is its path (/Player/Camera) or its numeric id (#4).

  burrow scene get scenes/main.voxscn                      list nodes: id, path, components
  burrow scene get scenes/main.voxscn /Player              the components of a node
  burrow scene get scenes/main.voxscn /Player transform    one component
  burrow scene set-component scenes/main.voxscn /Sun render.pointlight intensity=3 range=20
  burrow scene set-component scenes/main.voxscn /Sun render.pointlight '{"color":[1,0.8,0.5]}'
  burrow scene rm-component scenes/main.voxscn /Sun render.pointlight

set-component merges the given fields into the component (a new component starts empty); --replace replaces it
instead. field=value takes JSON (3, true, [1,2,3]) or else a string; "@-" as the single JSON argument reads stdin.
The whole scene is validated against the component registry (names, fields, types, ranges) before an atomic write;
on an error the file is not touched. The file is rewritten in the canonical form of the editor's Save.
flagtypedefaultdescription
-replaceboolset-component: replace the component instead of merging

burrowplay#

burrowplay [flags] <project dir | game.burrow> runs a project: window, headless simulation, screenshots and replays. burrow run forwards its flags.

flagtypedefaultdescription
-aastringanti-aliasing of the HDR shader levels: off, fxaa, smaa, taa (default: the shader level's preset); env BURROW_AA; overrides runtime.aa
-checkboolload the project/pak, verify it and exit
-cloudsstringcloud cover of the HDR levels: auto, clear, scattered, broken, overcast or 0..1; env BURROW_CLOUDS
-connectstringjoin a multiplayer server: a join link printed by burrow serve (burrow://host:7777?fp=...&key=...); the project must be the server's (docs/networking.md)
-cpuprofilestringwrite a Go CPU profile of the whole run to this file
-distortionstringair distortion (heat haze, shock waves) of the shader levels medium and up: off, on (default) or a strength 0..4; overrides runtime.distortion
-expectstringwith -replay: fail unless the replayed StateHash equals this hex value
-framesintwith -shot: frames to render before the screenshot (default 60)
-freezeboolwith -shot: freeze the simulation (no ticks while the shot settles) and the sky/water animation, for reproducible shots
-hashboolprint the final StateHash
-hash-everyintwith -headless: also print the StateHash every N ticks (finds the first diverging tick between two machines)
-headlessboolno window or GPU: step the simulation only (needs -ticks)
-heightintoverride window height
-journalstringwrite the session journal (JSON) here on exit
-jsonboolprint results as JSON
-levelstringstart in this level (id in the levels folder) instead of levels.initial
-namestringwith -connect: your player name (default: your user name)
-nocapturebooldo not capture the mouse
-novsyncbooldisable vsync
-radiusintoverride the terrain load radius (chunk columns)
-render-scalestringrender resolution: native, quality (67%), balanced (59%), performance (50%), 0.5..1 or 50..100; env BURROW_RENDER_SCALE; overrides runtime.render_scale
-replaystringreplay this journal JSON with the project's configuration and print the hash
-rtstringray tracing of the HDR shader levels: off, shadows (sun shadows + AO), full (+ GI and reflections) or a list of sun,ao,gi,reflections (default: the shader level's preset: high shadows, ultra full); env BURROW_RT
-saystringwith -connect: send this chat line once joined (lines typed on stdin are sent too)
-scenestringstart on this project-relative .voxscn instead of the project's default_scene
-scriptstringplay this JSON input script (frames of dt/keys/mouse) through the real controller and renderer (hidden window), then exit; with -timeline the per-frame times
-seeduintoverride the world seed
-shadersstringshader level: off, low, medium (default), high, ultra; env BURROW_SHADERS
-shotstringrender -frames frames, save a PNG here and exit (hidden window; needs the GPU)
-shot-atstringwith -shot: also save numbered PNGs (<shot>_001.png...) at these seconds of game time, comma separated (e.g. 0.5,1,2.5)
-shot-countintwith -shot-every: number of PNGs (default 5)
-shot-everyfloatwith -shot: save a numbered PNG every N seconds of game time, -shot-count times
-showboolwith -shot: show the window
-soundsstringfolder of your own sound files (sounds.json or a step/dig/ambient/music layout; docs/audio.md, "Sound packs"); env BURROW_SOUNDS; default ~/.burrow/sounds; never exported
-spawnstringwith -level: the spawn point to arrive at (default: the level's default spawn)

-ticksintfixed ticks to simulate (1 s = runtime.tick_rate ticks, 20 by default); with a window: run N real ticks first (journaled, replayable)

-ui-screenstringshow this game UI screen (docs/game-ui.md) from the first frame; with -shot it photographs any menu screen
-upscalestringupscaler for -render-scale < 100%: off (bilinear), fsr1, fsr2, dlss/xess (stubs; need their SDKs); env BURROW_UPSCALE; overrides runtime.upscale
-validateboolenable the Vulkan validation layer (slow; development only)
-versionboolprint the version
-widthintoverride window width

burrowedit#

burrowedit [flags] opens the editor. burrow edit forwards its flags and sets up the Vulkan environment.

flagtypedefaultdescription
-aastringviewport anti-aliasing: off (default), fxaa or smaa (temporal modes are game-only)
-agentstringserve the editor_* MCP tools on unix:<path> (socket 0600 in a 0700 dir); with -headless also stdio
-agent-allowvaluedirectory agent file operations (open/save/world) may use besides the open project; repeatable (default: only the project directory)
-assetstringwith -tool: project-relative asset to open (.bmodel, .vox, .png, .particles.json, .ui.json or any text file); empty = a new document
-cloudsstringcloud cover of the HDR levels: auto, clear, scattered, broken, overcast or 0..1
-cpuprofilestringwrite a CPU profile to file
-framesintrender N frames, screenshot, exit
-hintwindow height (0 = automatic)
-headlessboolno window or GPU: serve the editor tools only (needs -agent; screenshots use the CPU rasterizer)

-navboolinstall navigation and AI (also set by runtime.plugins.nav of the project)
-no-fine-waterbooluse the coarse water automaton (8 levels per block) instead of the adaptive fine water
-novalidationbooldisable the Vulkan validation layer
-novsyncbooldisable vsync

-radiusint8terrain load radius in chunk columns
-scenestring.voxscn to open
