Architecture and package map#

The design rules (two domains, stages, determinism, errors) are in ARCHITECTURE.md; this page is the map. Determinism, in one sentence: same project, seed and inputs give the same StateHash, on macOS Apple silicon and Intel (tested). Windows and Linux are checked by the CI workflow against a golden hash, which has not run yet. The simulation uses integer math or explicitly rounded floats with a deterministic math library; rendering is not covered. See Determinism.

A run of burrowplay#

internal/game.Build reads vox.project, then assembles plugins in this order: Scene, [Window], Assets (dry-run DB + wasm loader), VoxelWorld (generator from runtime), Input, Physics, Script, [Controller, Render], RenderWorld, extras. It builds the app, applies the journaled start-up commands (editor_world_load for runtime.world, scene_load for the default scene) and runs headless ticks (App.Frame(FixedDt)) or the windowed loop. Scripts can queue the same journaled scene_load at runtime with the scene_load host function (burrowsdk.SceneLoad("scenes/game.voxscn"), see script/ABI.md): the .voxscn file is read pinned by content hash like asset_read, so a replay loads the same document — a default_scene can be a menu that hands over to the game scene. RenderWorldPlugin is present even headless so scenes with render.* components load and hash identically in both modes.

  A["Read vox.project"] --> B["Assemble plugins"]
  B --> C["Apply journaled start-up commands<br/>editor_world_load, scene_load"]

  D -- yes --> F["Windowed loop"]

Dependencies#

github.com/tetratelabs/wazero (scripts), golang.org/x/image and golang.org/x/text (fonts), GLFW bindings and a vendored Vulkan binding (third_party_vulkan, MIT fork of goki/vulkan, a package of the engine module itself: import path burrow-engine/third_party_vulkan, cgo only). Everything else is the standard library.
