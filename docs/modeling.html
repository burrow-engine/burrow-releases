Modelling and texturing#

Burrow has built-in tools to make voxel models and pixel-art textures, for humans in the editor (Tools > Model editor and Tools > Texture Editor: each opens as a full-window docked panel, or in a separate window from the asset's right-click menu) and for AI agents through MCP (editor_model, editor_texture). Both are declarative and deterministic: you send a list of operations (ops), the same ops always give a byte-identical result, and the op list is stored with the asset so it can be edited later. Packages: model/ (voxel models), texedit/ (textures); windows editor/ui/model_ws.go, editor/ui/texture_ui.go, editor/ui/toolwin.go; tools editor/agent/modeltools.go.

Everything an agent needs is in the tool descriptions and this page. The loop is: send ops, look at the returned image, fix, repeat, save.

Textures also get surface relief: the texture editor's Relief section derives a height from the colours (dark = deeper), or reads a painted one (Painted: a grey layer named height, white = surface, darker = sunk; it is not part of the colours), builds a normal map from it and a constant specular map, and writes <name>_n.png / <name>_s.png next to the texture (see rendering.md, "Parallax relief").

Voxel models (.bmodel)#

A .bmodel is versioned JSON ("format":"burrow.bmodel","version":1): name, grid size (up to 256 x 256 x 256), a palette of materials (color #rrggbb, emissive 0..255, gloss 0..255, alpha 0..255), named parts (a part is a rigid bone: parent, pivot), attachment points (attach: a hand, a socket, a light position), the voxel grid (run-length encoded, gzip, base64, with a SHA-256) and the op list that built it. Decoding is strict: unknown fields, a bad version, a wrong checksum, oversize grids and corrupt runs are rejected (model.Decode never panics, fuzzed).

Axes: x right, y up, z toward the viewer (Burrow axes). A cell (x,y,z) fills [x,x+1). Box corners are inclusive cell coordinates; centres, pivots and attachment points are corner coordinates (center=[8,8,8] is the corner shared by the eight middle cells, so sphere center=[8,8,8] radius=3 is symmetric in a 16 grid).

Two ways to send ops#

JSON list (ops) or the text DSL (dsl), one op per line, op key=value ...; values are JSON or bare words (mat=wood, min=[0,0,0], colors=[a,b]); repeat count=4 offset=[2,0,0] { ... } opens a block; # starts a comment. model.ParseDSL and model.FormatDSL round-trip; editor_model {action:get} returns the stored recipe as DSL or JSON.

editor_model {"action":"ops","dsl":"size size=[16,16,16]\nmaterial name=wood color=#a67c45\nbox min=[2,0,2] max=[9,5,9] mat=wood"}

ops is all or nothing (one undo step; on error nothing changes and the error names the op index and the valid values). build replaces the model by building it from scratch. verify replays the stored ops and compares the result (the determinism check).

StampOp builds it; it is what Ctrl+C of the editor's model window captures.

Every other op takes layer:"name" to draw into that layer (default: the first); on repeat it applies to the body. See Layers and variants.

Determinism: all geometry is integer arithmetic on 1/32-voxel coordinates, noise is fixed-point hashed noise with an explicit seed; nothing reads a clock, a global random generator or map order. Limits (hostile input): grid <= 256^3, 4096 executed ops, repeat depth 4, a global evaluation budget (an op over the whole grid costs the grid volume), 255 materials, 64 parts, 64 attachments, 1 MiB of ops text, 64 MiB files; floats must be finite and within 512 voxels.

Layers and variants#

A model has ordered layers (up to 32, bottom first), each its own voxel grid of the model's size with a material and a part per voxel. They are composited bottom to top: a filled voxel of an upper layer replaces the one below. Layers are independent of parts (bones): one part can have voxels in several layers. A layer has a name, a hidden flag (editor visibility only: the game ignores it) and a locked flag (tools and ModelApply refuse edits to it).

A variant (up to 64) is a named list of layers shown together. With no variants every layer is shown; the first variant is the default. A campfire:

size size=[8,8,8]
material name=wood color=#6b4423
material name=fire color=#ff8a1e emissive=200
box min=[1,0,1] max=[6,1,6] mat=wood
layer name=flame
box layer=flame min=[3,1,3] max=[4,4,4] mat=fire
variant name=off layers=[base]
variant name=on layers=[base,flame]

All variants share one frame (the union of their bounds), so switching variant does not move the model. Draw into a layer with layer: on the ops. Old files are one layer called base; a model with just that layer is still written in the original format (version 1), others as version 2 (voxels stored per layer, plus variants); both versions are read. .vox export (export_vox {variant}) flattens the chosen variant; the asset loader gives render.voxmodel every variant.

Pick the variant a node shows with render.voxmodel.variant (empty or unknown = the default variant). A script switches it at run time, for instance field_set(node, "render.voxmodel", "variant", "\"on\"") (or entity_set_component) when a campfire is lit; the new variant is meshed once and cached. In the modeler, the Layers tab of the settings panel lists the layers (eye = hide in the editor, lock, click to make one active; add, duplicate, move up/down, rename, delete) and the variants (a checkbox per layer, rename, make default, delete, and a Preview selector that composites only that variant in the viewport). Tools paint, erase and fill into the active layer; every layer or variant change is one undo step. editor_model {action:layer_list} lists them for an agent (layers is the ASCII slice dump).

Recolor: colour variants without a new file#

render.voxmodel.recolor (and character.recolor) changes palette entries for one instance: index=#rrggbb[aa] entries separated by commas, with the 1-based palette indices of the .vox, for instance "3=#c02020,7=#2060d0" makes the red team and the blue team from one model. The recoloured mesh is built once per combination and cached, so there is no per-frame cost. A script sets it at run time with field_set(node, "render.voxmodel", "recolor", "\"3=#c02020\""). In the editor the inspector shows one colour row per colour the model uses (the 16 most used), with Reset colours. It composes with variant. A character with a built-in model (humanoid...) ignores it; use skin there.

Which way a .vox faces#

MagicaVoxel's front is its -Y side (what its default camera sees). render.voxmodel puts that side toward the engine forward (-Z, yaw 0), the same as a character made from the same file. There is no option: it is the only convention. A project made before it (vox_front absent or "legacy") is converted by burrow migrate, which turns its render.voxmodel nodes by 180 degrees about Y (and their direct children back) so they look the same. Bounds and editor picking follow the same front. The model editor's own viewport keeps its fixed view.

Feedback an agent gets#

editor_model returns stats (voxel count, bounds, colours with counts, per-part counts, mirror symmetry per axis for shape and colour, connected pieces and floating/disconnected voxels with their positions) and, for ops/build/load, a montage image: front (F), side (S), top (T) and isometric (I) views. preview {view,part,yaw,pitch} renders one view (part dims the others: the onion view). layers prints the voxels as ASCII layers (top layer first). Read the image after every batch: stats cannot tell you a nose is on the wrong side.

Scale and size references#

A block is one world voxel edge: 1 m at the default world voxel size 1, 0.25 m in a world with 0.25 m voxels. A model stores its target scale, voxels_per_block (default 16, so one model voxel is 6.25 cm and render.voxmodel scale is 1/16), optionally with a kind hint (prop, character, vehicle, building, item). Both are optional fields of the .bmodel (absent = 16 and no kind) and Model.PreferredScale() is the scale the model asks for when placed. Metres per model voxel = world voxel size / voxels_per_block.

The player is 1.8 m tall (28.8 model voxels at 16 per block), eye line 1.62 m, shoulders 0.6 m; a door is 1 m wide and 2 m high. Typical sizes: character height 1.2-2.5 m, item largest side up to 1 m, prop 0.1-4 m, vehicle 1.5-12 m, building 3-64 m; a model outside its kind's range gets a warning.

In the editor, the Advanced tab of Model Settings has a Scale section: voxels per block (drag or 8/16/32/64), the kind, the size in metres, blocks and voxels, the ratio to the player, a "fits a 1 x 2 m door" check and the warnings. Its toggles (also in the viewport menu, Scale references) draw over the viewport: a player silhouette, a one-block cube, a block grid on the floor, rulers along the bounds (metres, blocks, voxels), and a doorway with the 2 m door and 3 m ceiling lines. Changing the scale or the kind is one undo step.

Agents: editor_model results carry dimensions (voxels, blocks, metres, player_ratio, fits_door, warnings) and dimensions_text; the montage draws a blue player figure and a red one-block cube left of and behind the model at the same scale (no_reference turns them off). action: scale with voxels_per_block and/or kind sets the target scale; a rebuild keeps it and spawn uses it when scale is 0.

Assets, instances, bones#

  • save {path} writes assets/models/<name>.bmodel (project relative, confined to the project). export_vox / load handle MagicaVoxel .vox (parts become scene-graph nodes and come back as parts with their pivots; palette colours become materials c<index>; emissive and gloss have no .vox equivalent here).
  • .bmodel loads through the asset system as the same value as .vox, so it works wherever a .vox does: the render.voxmodel component (props, entities: editor_model {action:spawn} adds the node, saving again hot reloads it), character models ("model":"assets/x.bmodel") and the animation skeleton (anim.SkeletonFromVox: each part is a bone with its pivot, parent gives the hierarchy, the root part is the skeleton root; docs/animation.md). Model 0 of the loaded file is the whole model merged (what render.voxmodel draws), models 1.. are the parts.
  • Dynamic voxel bodies (physics3d): model.SolidMask() gives the dense occupancy array for physics3d.VoxelBody.
  • Block custom shapes: a 16 x 16 x 16 model gives BlockBoxes() / editor_model {action:block_shape}: boxes in sixteenths of a block with the axes and units of package shape (shape.Box). Registering a new shape family still means appending to the frozen shape.Models table (a source change); the boxes are the geometry to put there.
  • Scripts (read access only): burrowsdk.SpawnModel("assets/models/crate.bmodel", 0, burrowsdk.SpawnOpts{...}) spawns a node showing the asset by name. It is sugar over Spawn with a render.voxmodel component: no new host call, the script reads nothing, the sim is unaffected.

In the editor the model editor is a docked panel (Unreal-style asset editor): Tools > Model editor, or double-click a .bmodel / .vox in the Content browser, opens the Model panel in the dock (a tab next to the Viewport), with Model settings on the right and the Content browser below as the content browser. The panel has one header row (document name with an unsaved dot, Save, undo/redo, the Iso / Front / Side / Top views, Frame, and the ⋯ menu), the tool rail on the left with each tool's key on its button (B place, E erase, C paint, X box, O sphere, L line, F fill, T extrude, S select) and the viewport in the middle. Model settings has three tabs: Palette (the material grid with number keys, double-click a swatch for its colour picker, a Recent row, the selected material's name, colour, emissive and gloss, then the options of the active tool: Add or Carve for the shapes, brush size, mirror, Stay on the start plane, slice), Parts and Advanced (file, selection, modifiers, recipe, model info). The viewport is a real 3D render (perspective by default, orthographic with the header's Persp / Ortho switch or P; the picking uses the same camera; daylight lighting) when a GPU is available, with the software render as fallback. Save writes the asset path directly (Ctrl+S); New and Save-as are inline forms in Model settings (New also offers the embedded templates crate / lantern / tree / creature), Open is the Content browser — no modal dialogs. A separate OS window is still available (right-click the asset > "Open in a separate window", or Window > New window; burrowedit -tool model -project <dir> -asset <file>, a second process that saves into the project and the editor picks the saved file up).

Textures#

editor_texture edits one texture at a time: block textures 16 x 16 .. 128 x 128 (square or not), item icons, with layers. Ops are JSON:

fill, clear, `erase {rectpoints}`

pixel, line, rect {hollow}, ellipse {hollow}, flood {pos,color,tolerance}, replace {from,to,tolerance}pixel tools.

Limits: 128 x 128, 2048 ops, 8 layers, 1 MiB PNG, 128 x 128 ASCII cells. The same ops always give the same PNG bytes.

Feedback: ops returns the texture tiled 3 x 3 (read the seams), a block-in-world render (3 x 3 blocks with a pillar, isometric; give top/side/bottom texture names to see a real block), the mip chain, and stats: colours and counts, transparent pixels, wrap-around steps (seam_error_h/v) against the largest interior step and tileable_h/v. A grass side texture is meant to tile horizontally only.

Saving: the project override layer#

save {kind:block,name:"cobblestone"} or save {block:"grass_block", face:"side"} writes <project>/textures/block/<texture>.png (and the recipe <texture>.texops.json beside it). block+face resolves the pack texture name that face samples, so the override replaces exactly it (a texture shared by several blocks changes all of them). The bundled third-party pack (Pixel Perfection CC-BY-SA) is never modified: overrides live in the project, win over the pack, and are resampled to the pack size (16) because the layer table has one size (the PNG keeps its resolution). The running game (editor Play, burrow run) rebuilds its block texture layers on the next frame (blocktex.OverrideGeneration); burrow build packs only the folders listed in asset_dirs of vox.project: add "textures" there to ship the overrides. Item icons go to textures/item/. Tinted textures (grass top, leaves) are gray luma in the packs and biome tinted at render time.

In the editor the texture editor is a window of its own (Tools > Texture Editor, or double-click a .png in the Content browser; burrowedit -tool texture -project <dir> -asset <file>). Tools are on the left (B pencil, E eraser, L line, R rectangle, O ellipse, F fill, A replace colour, I picker, G gradient, plus the Hollow toggle for rectangle and ellipse, mirror left-right and top-bottom and the primary / secondary colours), the canvas takes the middle and the colours, layers, previews, generators and relief maps are on the right.

A block texture has three faces: the side is the main picture, the top and the bottom are drawn only when they differ (the header's Face selector; a new face starts as a copy of the side). Save writes <name>.png, <name>_top.png and <name>_bottom.png (the packs' naming), open reads them back, and undo goes back to the face it was made on. Layers can be hidden, locked (drawing tools refuse a locked layer) and blended (normal, multiply, screen, overlay) with an opacity.

One-click styles (Generate panel): pick a style (Stone, Planks, Bricks, Cobble, Metal, Grass, Sand, Ore, Fabric), a seed and a base colour, press Generate: the layer is cleared and rebuilt by a curated op stack (pattern, periodic noise, speckle, shading, seamless) as one undo step, the whole "patron" of a block texture. Strokes are filled in between mouse samples, so a fast drag leaves no gaps, and each stroke is one undo step. The brush size (pencil and eraser) goes up to 8. A texture made with New saves to textures/<block|item>/<name>.png (the override layer above); a .png opened from the Content browser saves back to that file. File > Save to a block face writes the texture over the one a block uses on a face. The status bar shows the pixel and colour under the pointer.

Examples (generated by these ops, original work)#

Each one is in docs/examples/; the tests build every file twice and require identical bytes. Montages: MODEL_MONTAGE_DIR=/tmp/m go test ./model -run Montages.

Animated creature with bones#

Parts are bones: body is the root, head, tail and the legs are children (the right legs are mirror ... name=leg_fr part=leg_fl copies). Load it as a skeleton with anim.SkeletonFromVox (or a character with this model) and animate the bone names in an .anim clip (docs/animation.md).
