0.8.4 - 2026-11-10

Latest2026-11-10

  • Fixed: the render scale (RenderSettings.RenderScale, BURROW_RENDER_SCALE, -render-scale) was silently ignored in hybrid frames (voxels plus scene meshes: any game with a held item, an animal or another player), which rendered at native size and also lost the SMAA the scaled request had replaced with FSR 1. The mesh phases already run inside the voxel main pass with its render-size viewport and camera, the object velocity pass is recorded at the render size and the canvas is drawn by the composite at the display size, so effectiveAA no longer forces native there. Measured on an M2 Max at ultra, 3456x2008: native 24.8 fps (GPU 40 ms), 75 % 36.9 fps (27 ms), 50 % 49.2 fps (17.6 ms).

  • Changed (performance): per-chunk draws of the main and shadow passes are recorded by one cgo call per pipeline (vulkan.CmdChunkDraws, third_party_vulkan/chunk_draws.go): the loop in C rebinds the buffer and pushes the constants only when they change, instead of four cgo calls per draw. About 6 % less main-thread time in recordVoxelPass at ~2 500 draws; the rest is MoltenVK's own work per draw.

  • Added: a dedicated server pauses when nobody plays, as Minecraft's pause-when-empty-seconds. server.json pause_when_empty_seconds (60 by default, absent in an old file = 60; 0 = never): once no player has been connected for that long the server saves the world and runs no tick (no CPU, the world and its clock wait; autosave skipped while paused), connections are still accepted and the ticks resume as soon as a player is authenticated, without catching up the paused time. replica.ServerConfig.PauseWhenEmpty, Server.Idle, netplay.HostOptions.PauseWhenEmpty, netplay.Server.Idle; status reports paused. Tests TestPauseWhenEmpty, TestConfigDefaults. Branch dedicated-pause-when-empty.

  • Added: linked custom blocks (links, link_faces, arms in blocks/custom_blocks.json; shape.CustomSpec.Links, LinkFaces, Arms; DeriveLink): a block joins named link groups (at most 32 per project, Model.Link mask) and connects on a face to a neighbour that shares a group when both allow the faces between them (Model.LinkFaces, authored facing north and turned with facing; Model.Links). With arms it has 64 derived variants, its boxes plus the arm boxes of each connected face (collision, selection, look), so a pipe, a cable or a shaft shows a branch toward each connected neighbour only; a block with links and no arms (a pump, a machine) keeps one look and makes its neighbours reach it. Nothing is stored: a save keeps one state per block, ids do not move. Validation: arms need links, arms only on allowed faces, model plus arms within 32 boxes, not with planes or round. Tests TestLinkedPipeBranchesTowardItsGroupOnly, TestLinkedShaftLinksAlongItsAxisTurnedWithFacing, TestLinksAreValidated. Branch gogame-block-links.

  • Added: moon phases in the HDR sky. engine.RenderSettings.MoonPhases / MoonPhase (lunar age as a fraction of the cycle: 0 new, 0.25 first quarter, 0.5 full, 0.75 last quarter; Renderer.SetMoonPhase) draw the disc lit on the side of its phase (waxing on the right, a faint earthshine on the dark side, shaders/atmo.glsl, carried by the free S.fx.x), and the moonlight follows it: direct light and moonlit ambient (scene.Sky.AtmoMoon, scene.MoonLight: 12 % of the full moon's at a new moon), the moon's light on clouds and on falling water. Off by default (a full moon, as before). Capture aids BURROW_MOON=<age> and BURROW_SKY_TIME=<0..1>. Rebuilt sky_hdr.frag.spv, water_hdr.frag.spv. Tests TestMoonLightFollowsThePhase, TestMoonPhaseUniform. Branch gogame-moon-phase.

  • Added: local weather (weather.LocalWeather, weather/local.go): the installed Climate may also implement WeatherOverride(seed, x, y, z, clock) (kind, intensity, ok), which At asks first. KindClear stops any precipitation there (even under a raining front; cover at most 0.25, no fog), KindCloudy is overcast and dry, KindFog dense fog, rain kinds and KindSnow fall with the given intensity (rain or snow by the temperature, Lightning in a storm). Local.Override reports it. State, hash and snapshots are unchanged. RenderFX takes the cloud cover, overcast, sunlight, wetness and fog from the camera's place when it is overridden (before, only the precipitation and the fog density followed the place, the sky followed the front), and a local storm under a front that is not a storm draws flashes from the seed and the clock. Tests TestLocalWeatherDisks, TestLocalWeatherRender. Branch gogame-weather-local.

A flyer agent without physics.character was already moved in 3D by the plugin (no gravity, 26-neighbour A*); wander, flee and the new hover {alt,tol} now keep a cruising height of alt metres above the ground under the agent (World.Ground: the first solid, micro or liquid cell below; a roof lowers it), the argument falling back on the blackboard number fly_alt (nav.FlyAltKey) that rules set with Ctx.SetBlackboard; wander jitters it by alt_var metres, flee never descends, hover climbs or sinks to it and stops. chase, move_to and look_home take above (metres over their point).   • Changed: movement authority, as in Minecraft. A predicting client now sends with every input where its own walk put the player (netsim.Input px/py/pz/pvy/hp/tp, netsim.WithClaim) and the server takes that position when it is plausible (net/netsim/authority.go, claimOK): a horizontal distance budget refilled every tick at the fastest allowed speed (×1.4, one second of burst), the climb allowed off the ground, a liquid or a ladder (Rise: 1.25 jump heights plus a step), the vertical speed, and the body box swept from the node to the claim (vertical then horizontal, or the reverse) must reach it. Before, the server walked every input itself and the client was corrected (rolled back and replayed) as soon as the two disagreed. Now the server answers with a teleport (netsim.Player.TP, replicated in the public registry) only when it moved the node itself (a game rule: knockback, teleport, mount, respawn: the node is not where the last input left it, Player.Last) or refused a claim (it then walks that input itself); the inputs computed before the client saw the teleport are walked by the server, and the client (internal/netplay/predict.go) snaps and replays only on a new teleport number. Inputs without a claim (other clients, lockstep, tests) are walked as before. The registry encoding gains flags 8 (TP, Rise, Budget, BudgetTick) and 16 (Last), absent while zero: older states decode and hash unchanged. Measured with a windowed client on a local dedicated server, running in circles for 40 s: 1278 inputs, all claims taken, no correction. Tests TestHonestClaimsAreNeverCorrected, TestCheatedClaimsAreRefused (speed, wall, flight), TestServerMoveIsATeleport, TestAuthorityStateRoundTrips, TestPredictionMatchesTheServerExactly (claims).

  • Fixed: a replicated client animated everything by the integer tick of the last server frame (FrameState.Tick, set by ReplicaSetTick when a frame arrives): rain and snow streaks, water waves and swell, swaying leaves, clouds and animated textures stood still on most frames and jumped when frames came, unevenly (measured on a client at ~107 frames per second: 81 % of frames without motion, 19 ticks/s ± 40). The renderer now draws with a smooth animation clock (render/vulkan/animclock.go, as a Minecraft client ticks its own time between the server's updates): it advances with the wall clock between ticks, follows the tick without going back, freezes at most 2 ticks past the last one, stays exactly on a fixed tick (tests, frozen screenshots) and snaps on a jump; same measure after: 0 % of frames still, 20.0 ticks/s ± 0.4. Test TestAnimClockIsSmoothBetweenBurstyTicks. Branch gogame-smooth-anim-time.

  • Changed (performance): the HDR main pass no longer draws all terrain with one discarding pipeline. The solid range of the chunks that are not cross-fading is drawn first with voxel_hdr_solid.frag (NO_DISCARD: a shader that may discard turns off the early depth test and the hidden surface removal of tile-based GPUs for everything it draws); the cut-out range (leaves, grass, flowers, custom planes) then gets a depth prepass (voxel_hdr_pre.frag, DEPTH_PREPASS: the alpha test alone, no colour written: pipeDesc.noColor) and is shaded at depth EQUAL without discard (pipeDesc.depthEqual), so each visible foliage pixel is shaded once; cross-fading chunks and the slice view keep the discarding pipeline. BURROW_LEAF_PREPASS=0 turns the prepass off. Measured in a forest overview (M2 Max, 1280x720, ultra): 22-24 ms GPU -> 14.3 ms (solid split alone: -1.2 ms), images identical; the low/medium non-HDR levels are unchanged. Tried and dropped (no measurable gain): back-face culling in the shadow pass, skipping the sun shadow taps for empty cut-out texels.

Such planes cover nothing (a trunk behind holey leaves keeps its faces). quadHidden takes the footprint of a plane that leaves the cell within the face. Test TestPlanesAttachedToAFaceHideBetweenNeighbours.

First public version of Burrow: a deterministic voxel game engine in Go, with an editor, scripting, a Vulkan renderer and an interface made for AI agents. Early version, MIT licensed.

Engine#

  • Same seed and same inputs always give the same world, so any session can be replayed (burrow test).
  • Voxel worlds with biomes, rivers, mountains and caves, plus physics, pathfinding, particles, weather and water.
  • Scene tree with prefabs and saves, a game UI toolkit and six camera types (first and third person, top-down, isometric, side-scroller, cinematic).
  • Nine project templates: sandbox, builder, scripted, platformer, physics puzzle, top-down strategy, survival, models, empty.

Rendering#

  • Vulkan renderer with quality levels from off to ultra: sky, clouds, shadows, ambient occlusion, bloom, water reflections, rain, snow and storms.
  • Anti-aliasing and upscaling (FXAA, SMAA, TAA, FSR 1 and 2) and optional ray tracing.
  • A CPU renderer makes the same images without a window or GPU, for tests and screenshots.

Editor and tools#

  • burrowedit: viewport, hierarchy, inspector, asset browser, profiler, terrain tools, undo and redo, Play mode and built-in tutorials.
  • burrow command line: new, run, edit, test, build, script, assets, doctor, docs.
  • Everything the editor does also works headless over MCP and a JSON CLI.

Scripting#

  • Scripts are written in Go, compiled to WebAssembly, or built as visual graphs with no code.
  • They run inside the simulation, so they replay like everything else.

Hub and distribution#

  • Burrow Hub manages projects and engine versions, opens the editor, plays and exports.
  • Update checks are optional and only signed manifests are accepted.
  • No telemetry is sent.
  • A Windows x64 download holds the editor, Hub, command line, script SDK, docs and templates.
  • A website hosts the documentation, news and this changelog.

Known limits#

  • This is an early version and the API may change.
  • Windows builds are untested on real hardware and unsigned, so SmartScreen may warn.
  • Windowed use is supported on macOS Apple silicon only.
  • There is no multiplayer yet.
  • Textures are not animated, and blocks added after Minecraft 1.16 use flat colours.
